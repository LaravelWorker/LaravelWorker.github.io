Тесты и приёмка

Логику, где ошибка стоит денег — расчёты, списания, обработку ответов внешних API, — закрываю автотестами: PHPUnit и Pest на бэкенде, Jest или Vitest в Node-части. Перед релизом прогоняю сценарии руками: автотест ловит регрессию, ручная приёмка — то, чего не было в задаче.

PHPUnit · Pest · Jest / Vitest · ручная приёмка

Интеграция LLM в продукт

Подключаю языковые модели как обычный внешний сервис: потоковые ответы, обработка таймаутов и отказов, повторы, ограничение расходов, кеширование одинаковых запросов. Стоимость запроса считаю до того, как она станет строкой в счёте.

antifragile-trading.ru
Единственный разработчик · полный цикл · 1,5–2 месяца до продакшена
Задача
У заказчика — независимого инвестиционного советника из реестра ЦБ РФ — продажа клубных подписок и приём оплат велись вручную. Требовалось автоматизировать продажу и продление подписок, регулярные списания и доставку аналитики клиентам — с соблюдением 54-ФЗ.
Что сделал
Экосистема из трёх частей на общем бэкенде: админ-панель, Telegram-бот и бот для MAX. Две платёжные интеграции с рекуррентными списаниями и обработкой вебхуков. Идемпотентность по external_id провайдера — двойные списания и дубли подписок исключены на уровне модели. Фискализация по 54-ФЗ, полный жизненный цикл подписки и разграничение доступа к платному контенту.
Результат
Заказчик больше не участвует в приёме платежей — продажа и продление подписок идут без ручных операций. Бот для MAX добавлен, когда часть аудитории ушла из Telegram: канал доставки не потеряли.

02

Бэкенд сервиса автоматизации фьючерсной торговли

tradingforce.io · проект закрыт
Единственный backend-разработчик в команде из четырёх · проектирование архитектуры вместе с лидом
Задача
Автоматизировать фьючерсную торговлю на бирже Bybit: три отдельных бота под разные категории пользователей и веб-кабинет с графиками.
Что сделал
Спроектировал и реализовал всю серверную архитектуру: интеграция с торговым API Bybit и REST API для фронтенда. Автоматическое выставление stop-loss и take-profit при достижении заданной цены. Слой рыночных данных: котировки поставлял отдельный Python-сервис через Redis, на своей стороне — дедупликация запросов с кешированием ответов, чтобы не обращаться наружу повторно за уже полученными данными. Отдельно — API для построения графиков во фронтенде. Торговую логику закрывал автотестами, перед выкаткой прогонял сценарии руками.
Результат
Проект закрыт — продукт не нашёл своего места на рынке. Серверная часть была собрана целиком и работала: боты, автоматика стопов и тейков, рыночные данные, API кабинета.

03

Мониторинг парка майнингового оборудования

Разработчик · полный цикл · заказчик под NDA
Задача
Оборудование распределено по разным сервисам и пулам. Простой отдельной машины замечали случайно — были случаи, когда устройство не работало неделями. Требовалось видеть состояние всего парка и узнавать о сбое сразу.
Что сделал
Сбор телеметрии по API нескольких сервисов и пулов — до 10 000 устройств с опросом раз в минуту. Двухуровневое хранение: оперативные метрики в Redis, суточные агрегаты в PostgreSQL — минутный опрос парка такого размера не раздувает базу. Контроль uptime, температуры и просадок производительности с настраиваемыми порогами, уведомления в Telegram и на email.
Результат
Простой машины виден через 3 минуты вместо недель. По каждому устройству — история метрик за весь период наблюдения.

SEO-платформа «Титло»

titlo.ru
Один из двух разработчиков · свои модули вёл самостоятельно — от постановки до продакшена
Задача
Расширить платформу инструментами текстового и конкурентного анализа. Аналоги у конкурентных сервисов существовали, но заметно уступали по возможностям.
Что сделал
Три инструмента с нуля: анализ релевантности, анализ текста, анализ конкурентов. Сбор поисковой выдачи через API Яндекса и Google — до 30 конкурентов на запрос, пакетная обработка списков ключевых фраз. Собственная реализация TF-IDF: облака словосочетаний страницы и конкурентов, плотность фраз, зональное сравнение и готовые рекомендации. Тяжёлые расчёты — в фоновых очередях, со статусом и процентом выполнения в реальном времени; результаты сжимаются при записи в базу и распаковываются на отдаче.
Результат
Полный анализ по запросу занимает 1–5 минут. Инструменты работают в продакшене по сей день и входят в основной функционал платформы.

Учебный центр для детей · Томск

Преподаватель веб-разработки · группы школьников · обучение на Moodle

До диплома и первой работы в коммерческой разработке вёл курс веб-разработки для школьников: HTML, CSS, JavaScript и основы работы с сервером. Занятия и домашние задания шли через Moodle — и под неё же я писал плагины на PHP, когда штатных возможностей платформы не хватало.

  • Вёл группы по 10–12 человек: программа курса, материалы, разбор домашних работ, итоговые проекты учеников.
  • Плагин проверки вёрстки (тип сдачи задания). Ученик отправлял HTML и CSS прямо в задание, плагин рендерил превью, сверял результат с эталонным макетом и прогонял валидатор разметки. Ребёнок сразу видел конкретный разбор — «картинка без alt», «незакрытый тег», «блок уехал вправо», — а не ждал следующего занятия. Типовые ошибки уходили ещё до того, как работа попадала ко мне.
  • Плагин отчётов по группе. Сводка прогресса для преподавателя: кто на какой теме, сколько попыток ушло на задание, где группа застревает массово — значит, тему надо переобъяснить. Раз в неделю отчёт по ученику уходил родителям на почту, что закрыло постоянные вопросы «как он там занимается» и помогло вовремя вытаскивать отстающих.
  • Сопровождение собственных плагинов при обновлениях Moodle, настройка курсов, ролей и прав доступа в системе.
